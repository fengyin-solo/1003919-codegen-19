# 地质灾害隐患点监测防治管理系统

面向地质灾害隐患点形变裂缝观测、雨量预警、避险搬迁安置与治理工程验收全流程的地质灾害防治数字化管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `geohazard-monitor-prevention:entries` 这一项，或调用 `resetModule(模块)`。

## 群测群防培训考核回传包

业务逻辑集中在 `frontend/src/api/training-package.ts`：

1. **导出签到表**：在群测群防培训页填写培训主题、培训对象，按二者筛选出未归档培训，
   导出带「包号」的 CSV 签到表（BOM、引号转义，Excel 可直接编辑）。
2. **讲师回传**：外部讲师在签到表上补录授课人、参训人数、授课记录、考核结果（可选合格人数/通过率），
   原 CSV 回传平台。
3. **逐条合并与结业建议**：
   - 身份/计划字段（培训编号、主题、对象、日期）以平台课程计划为准，对不上即判该记录失败；
   - 实施/考核字段（授课人、参训人数、授课记录、考核结果、通过率）以回传包为准覆盖平台旧值；
   - 通过率支持 `85`、`85%`、`85.5` 写法；给了合格人数可自动折算通过率，二者矛盾（误差>1%）判失败；
   - 旧培训缺考核通过率时按空值兼容，结业建议给出「补测后核发结业结论」；
     ≥90% 准予结业并优先纳入骨干宣讲员，≥80% 准予结业，≥60% 补训薄弱科目，否则重新培训考核；
   - 合并后培训状态流转为「已考核」。
4. **整包退回**：任一记录失败（编号不存在/已归档、身份字段冲突、缺授课记录、人数非法、
   合格人数超参训人数等）整包退回，培训、宣传、台账均不落库，页面列出每条失败的 CSV 行号与原因。
5. **幂等**：已合并回传包登记在 localStorage 台账（`geohazard-monitor-prevention:training-return-ledger`），
   包号或内容指纹任一命中即拒绝，同一包只合并一次。
6. **归档保护**：已归档培训不进签到表；手工构造的包即使含归档编号也会被该行判失败而整包退回。
7. **后续宣讲事项**：合并成功后，防灾宣传页按每条培训生成一条「培训成果宣讲」待开展活动
   （编号 `PROP-FU-xxxx`，计划日期为培训日后 30 天，带来源包号和来源培训编号可追溯）。
